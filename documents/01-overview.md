# 概要

## Docfillyとは

Docfillyは、文書の先頭に記述した設定項目から入力フォームを生成し、入力値を本文へ反映する可変ドキュメントフォーマットです。文書を作る人も使う人も、プログラミングの知識を必要としないことを目指しています。

Docfillyはプログラマー向けの汎用テンプレートエンジンではありません。条件分岐やスクリプトなどの高度な機能より、見ただけで理解できる書式、Markdownとしての読みやすさ、記述ミスがあっても本文を表示できる寛容さを優先します。

たとえば、次のような用途に利用できます。

- 環境ごとに内容が変わるセットアップ手順書
- プロジェクト名や担当者を差し替える案内文書
- オプションを選択して生成する設定例
- チェック項目によって値が変わるプレーンテキスト

## 主な機能

- 文字列から設定項目と本文を解析
- テキスト、ドロップダウン、チェックボックスを自動生成
- `[[設定名]]`をフォームの値へリアルタイムに置換
- Markdownとプレーンテキストの表示に対応
- MarkdownをHTMLへ変換し、危険なHTMLをサニタイズ
- 生成フォーム、出力要素、出力ソース、現在値をAPIから参照可能
- CRLFとLFの改行コード、UTF-8 BOMに対応
- 区切りがない通常のMarkdown／テキストもそのまま表示
- 先頭の`#!docfilly`で可変ドキュメントであることを明示
- 読み取れない設定行を注意点として報告し、残りの文書を描画
- 日本語の設定名に対応

## 設計方針

1. **文書が主役** — Docfilly独自記法は先頭の`#!docfilly`、設定項目、`[[設定名]]`だけに限定します。
2. **見て分かる** — 専門的な型名、式、プログラム構文を持ち込みません。
3. **止めずに表示する** — 軽微な記述ミスでは例外を送出せず、利用できる部分で描画を続けます。
4. **修正方法を伝える** — 読み飛ばした箇所や補正した内容は日本語の注意点として返します。
5. **安全に表示する** — MarkdownのHTMLはサニタイズし、フォーム入力はHTMLとして実行しません。

## 処理の流れ

1. アプリケーションが文書のソース文字列を取得します。
2. `createDocfilly`へソースと種類（`"md"`または`"text"`）を渡します。
3. 先頭が`#!docfilly`なら、区切り行より前の設定項目を解析します。
4. 識別子がなければ、通常文書としてソース全体を本文にします。
5. 設定の種類に応じたフォーム部品を生成します。
6. 本文中のプレースホルダーを現在のフォーム値に置換します。
7. MarkdownはHTMLへ変換、テキストはそのまま表示します。
8. フォーム変更後、既定では200ミリ秒待って再描画します。
9. 読み取れない記述があれば、描画結果と一緒に注意点を返します。

## モノレポ構成

```text
Docfilly/
├─ apps/
│  └─ web/                  Webデモ
├─ packages/
│  └─ docfilly/             ライブラリ本体
├─ documents/               プロジェクトドキュメント
├─ package.json
└─ pnpm-workspace.yaml
```

ライブラリはViteのライブラリモードでES ModulesとCommonJSを生成し、TypeScriptの型定義も出力します。Webデモはpnpm workspaceを通じてライブラリのソースを参照します。

## 対応環境

DocfillyはDOM APIを利用するブラウザ向けライブラリです。`document`、`HTMLInputElement`、`CustomEvent`などが存在する環境を前提とします。Node.js上でDOMを生成する場合はjsdomなどのDOM実装が必要です。
